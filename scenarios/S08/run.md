# S08 - Shareable layer without identity data

**Claim A6.** Tessiture Monteverde S.r.l. is held by a person and by Holding Aurelia Partecipazioni S.r.l., held in turn by two persons. The failure reproduced is identity data leaking into a document meant to be shared. Pass: none of the 15 strings of the identity layer (identifiers, names, dates of birth, tax codes, mail addresses) is found in the shareable DOCX (every XML part), in its provenance file or in the graph; the graph has the same four edges with the same exact shares and the same effective holdings, with persons under opaque ids recomputed by the check; the internal dossier does carry the names. This separates two layers; it is not access control. Since v2.0.8 each deed is followed by a registry extract that repeats it: an address is a fact only when a second document states it alike (`rules/extract.json` ADR-020), and a deed alone keeps every field `[TO CONFIRM]`. Expected values: `expected/expected.json`, written by hand in `scenarios/make_inputs.py` and never copied from a run. Everything is synthetic; what passes here is internal consistency, not accuracy on real companies.
